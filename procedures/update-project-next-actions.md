# Update Project Next Actions

Use this procedure when completed, changed, or newly created work changes what should happen next.

## Steps

1. Identify the active Project from the workspace pointer or user request and read its current actions plus only the context needed to reconcile them.
2. Remove completed items unless a completion is a meaningful milestone. Rewrite partial items to describe remaining work and merge overlaps.
3. Keep 3–7 outcome-level actions by default. More than 10 is a compactness warning; consolidate or use a dedicated task system.
4. Route consequential uncertainty, reusable knowledge, ongoing ownership, repeatable workflows, and decisions to the appropriate existing Type when direct and high-confidence.
5. If an action changes project state, scope, questions, links, workflows, or guardrails, refresh those sections through [[procedures/update-project-summary|Update Project Summary]].
6. Add a Maintenance Log entry only for a meaningful transition or decision, keeping the latest 3–5 milestones.
7. Reconcile the human view when the active workbench changed, then review the diff.

Phrase actions as outcomes, not microtasks. Do not keep a routine Done section, hide durable Questions inside actions, append near-duplicates, or attempt speculative broad cascades.
